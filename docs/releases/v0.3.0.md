# v0.3.0 — Native stdio foundation

Status: release candidate; publication is pending CI on the release commit. M1 is the implementation milestone; v0.3.0 is the intended source release. This is a pre-1.0 API with breaking changes from v0.2.0.

## Added

- Embed a C++23 MCP server in a native application using the `synapse::mcp` CMake interface target. The target propagates C++23, Threads and qualified header dependencies.
- Expose registered tools, static resources and prompts with typed text results under MCP `2025-11-25`.
- Validate tool arguments against compiled schemas before application callbacks. Dependency sources and the schema correction are pinned.
- Configure local queue/rate limits, tool authorization and output policies. Applications remain responsible for domain permissions and redaction.
- Use `native_status` to exercise real application state through `app.status`, `app://status` and `explain_status`.

## Changed and fixed

- Replace detached application work with an owned worker, bounded queue and explicit stop/join lifecycle. Cancellation is cooperative for application callbacks.
- Bound native stdio framing and buffered output; interrupt SDK-owned I/O during shutdown on Windows pipes and POSIX streams.
- Reject malformed RPC envelopes and invalid lifecycle operations before dispatch; handle numeric parse failures and enforce frame/resource boundaries.
- Check source-tree consumption, independent-client interoperability and raw-process shutdown in the hosted test matrix.

## Migration from v0.2.0

Registration now accepts descriptors and typed handlers and returns `std::expected`. Register before startup and check registration/start/wait errors. Keep the borrowed transport and captured state alive until all owned work is joined. Reverse server requests and pending server futures were removed. See the [migration guide](../migration/v0.2-to-m1.md) for signatures and callback restrictions.

Version metadata in CMake, the default server identity, reference executable and reference test fixture is updated to `0.3.0`. Historical test transcripts retain their original `0.2.0` identity.

## Verification and limits

The [M1 record](../verification/m1.md) documents the qualified source `1fa654be73d582e9ae4778da0d757e9112a6bac1`: Windows 118/118 and Linux functional, ASan+UBSan and TSan 117/117 per job, plus official-client and Inspector walkthroughs. Those counts describe recorded runs, not a claim that the release commit has already passed CI. README commands retain that historical pin for reproducibility.

Before publishing, require successful Windows, Linux functional, ASan+UBSan and TSan jobs for the exact release commit, then create the immutable `v0.3.0` tag at that commit. Do not reuse CI from a parent commit as release evidence.

Local candidate verification on 2026-10-30: the Windows Debug build completed and all 118 CTest checks passed in 105.65 seconds after the version changes. The 33 local file links in the edited documentation resolved and `git diff --check` passed. This run used the existing `build/t10-msvc` tree, not a fresh checkout; the earlier [clean-checkout README run](../verification/readme-2026-10-29.md) remains separate evidence.

This source release provides no prebuilt binaries or installed package export. Client, subprocess and SSE APIs remain experimental. HTTP/OAuth, subscriptions, sampling, roots, elicitation, completion and protocol logging are outside the qualified server scope. Other hosts/toolchains and MCP `2026-07-28` are unverified. A non-cooperative application callback can delay destruction.
