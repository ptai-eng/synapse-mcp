# Migrate the v0.2 server to the M1 runtime

This guide compares the experimental server at `22c2126` with verified runtime source `1fa654be73d582e9ae4778da0d757e9112a6bac1`. CMake and the reference application still report `0.2.0`; M1 names a milestone, not a published release. The [verification record](../verification/m1.md) records the qualified toolchains, named-host walkthrough and documentation reproduction.

## Build through CMake

Require CMake 3.20+, Git, C++23 and a standard library with `std::expected`. Link `synapse::mcp` through `add_subdirectory`; the target propagates C++23, Threads and its header dependencies. A header-only core still needs those transitive dependencies. This checkout provides no installed `find_package` export or package-manager release.

```cmake
add_subdirectory("path/to/synapse-mcp" synapse-sdk)
add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE synapse::mcp)
```

Downstream examples/tests default OFF; top-level examples/tests default ON. CMake uses checked-in nlohmann/json 3.11.3 and fetches pinned jsoncons/SRELL sources. An uncached configure needs Git/network access. Do not supply an unrelated parent JSON target or override qualified dependency sources. See [dependencies](../third-party.md) and [reproduced commands](../verification/m1.md#clean-checkout-reference-and-consumer).

## Replace callbacks and registration

All registration functions now take a descriptor and typed handler and return `std::expected<void, sdk_error>`. Check registration and `start()` errors. Register before `start()`; startup freezes registries. The server does not support restart.

| v0.2 server | M1 server |
|---|---|
| `register_tool(name, description, schema, callback)` | `register_tool(tool, tool_handler)` |
| JSON-returning `tool_callback(args)` | `expected<tool_result, handler_error>(args, context)` |
| `register_resource(uri, name, description, callback, mime)` | `register_resource(resource, resource_handler)` |
| JSON-returning `resource_callback()` | `expected<resource_result, handler_error>(context)` |
| `register_prompt(name, description, arguments, callback)` | `register_prompt(prompt, prompt_handler)` |
| JSON-vector `prompt_callback(arguments)` | `expected<prompt_result, handler_error>(arguments, context)` |
| `void start()` / `void wait()` | `expected<void, sdk_error> start()` / `wait()` |
| Server `send_request()` and pending futures | Removed; M1 sends no reverse server requests |

Use `tool_result{text}` and `resource_result{text}`. For prompts, return `prompt_result` with `prompt_message{prompt_role::user, text}` or `prompt_role::assistant`; the description is optional. Serialize application JSON with `.dump()` when you want JSON inside text. M1 handlers expose no arbitrary JSON content blocks, images, audio or embedded resources.

```cpp
#include <synapse/server.hpp>

int main() {
    std::string application_text = "ready";
    synapse::stdio_transport transport;
    synapse::server server(transport, {"my-app", "1.0.0"});
    auto registered = server.register_tool(
        {"app.status", "Read application state",
         nlohmann::json{{"type", "object"}, {"additionalProperties", false}}},
        [&application_text](const nlohmann::json&, const synapse::request_context&)
            -> std::expected<synapse::tool_result, synapse::handler_error> {
            return synapse::tool_result{application_text};
        });
    if (!registered || !server.start()) return 1;
    if (!server.wait()) return 1;
}
```

This declaration order keeps captured state and borrowed transport alive through the server destructor and joined work. Construct and destroy the server on its owner thread. Only one owner waits at a time. Handlers and custom policy hooks run on one owned application worker; coordinate access from other application threads. A server mutex does not protect external state.

## Handle cancellation and shutdown

`request_context` carries the request ID and `std::stop_token`. Poll `context.stop.stop_requested()` in long-running work and return when cancellation arrives. `stop()` requests cancellation, cancels queued callbacks without invoking them and interrupts SDK-owned I/O. It does not join. A callback may call `stop()`; callback-side `wait()` or `wait_for()` returns `invalid_state`. Do not destroy the server inside a callback.

The owner calls `wait()` to join. `wait_for(duration)` returns `false` if work remains; keep the server, transport and state alive after that result. The destructor calls stop and wait, so a non-cooperative callback can delay destruction until it returns. Tests enforce a two-second reference-process exit after EOF for idle/cooperative work; this is not a deadline for arbitrary application code. The transport allows a 250 ms output flush before aborting SDK I/O. Native Windows support covers pipe-backed stdio.

## Update protocol and errors

M1 negotiates exactly `2025-11-25`. Send `initialize`, inspect the returned revision, then send `notifications/initialized` before application methods. The v0.2 `initialized` spelling and partial `2024-11-05` behavior do not carry forward. The server replies to `ping`, ignores unknown notifications and validates envelopes before dispatch.

The registered surface covers `tools/list`, `tools/call`, `resources/list`, `resources/read`, `resources/templates/list` (empty), `prompts/list` and `prompts/get`. Capability advertisement follows registered features. Subscriptions, list-change notifications, completion, sampling, roots, elicitation, protocol logging, HTTP/OAuth and modern-era discovery remain outside M1. Client, subprocess and SSE APIs remain experimental.

Tool registration requires an object schema with `type: "object"`; compilation validates it before serving. The adapter defaults to JSON Schema 2020-12, validates declared dialects and resolves only bundled/preloaded schemas offline. Public tool registration supplies an empty external catalog. `format` remains annotation; validation neither populates defaults nor fetches URLs/files.

Malformed parameters, wrong argument types and unknown tools produce RPC errors. A schema mismatch or tool `handler_error` produces `isError: true`. Resource absence uses `-32002`. Use `handler_error.public_message` only for text safe to disclose; the SDK hides native exception details. `sdk_error` reports local registration/lifecycle/I/O failures and differs from wire `error`.

## Set local policy

Each server defaults to 16 pending requests, one active application callback, and a shared tool token bucket with burst 16/refill 16 requests per second. These limits apply per server instance, not per user or tool. An empty `allow_tool` admits registered tools. Supply `allow_tool(name, context)` for narrower authorization; it runs before quota, schema validation and callback execution. Denial, rate exhaustion and queue exhaustion use `-32050`, `-32051` and `-32052`.

The built-in output checks reject invalid UTF-8, controls below U+0020 except TAB/LF/CR, DEL, and oversized encoded responses. They do not detect secrets, prompt injection or sensitive domain content. Supply `filter_output(operation, text, context)` for application redaction; the SDK rechecks returned text. Hooks run on the application worker and must cooperate with shutdown too.

`stdio_options` defaults to 1,048,576 bytes per frame (excluding LF), JSON depth 64 and 4,194,304 queued output bytes (including LF). These are local configuration, not negotiated host limits. Keep stdout for UTF-8 newline-delimited JSON-RPC and diagnostics on stderr. See the [native reference](../../examples/native_status.cpp).
